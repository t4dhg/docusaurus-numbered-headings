# Dependency risk

_Assessment date: 2026-08-26._

## Audit boundary and current results

The package has two distinct dependency-risk surfaces:

- `npm audit --omit=dev --audit-level=high` exited `0` with zero
  published-surface vulnerabilities. This is the release-blocking audit gate.
- `npm audit --json` exited `1` with 31 development/build vulnerability
  entries: 2 low, 8 moderate, 21 high, and 0 critical. This full tree is not
  clean.
- `npm audit fix --dry-run --package-lock-only --json` exited `1` because the
  findings remain, but proposed `0` additions, `0` changes, and `0` removals.
  There is currently no compatible lockfile-only remediation calculated by npm.
- Registry queries reported `3.10.2` as the latest version of both
  `@docusaurus/core` and `@docusaurus/preset-classic`.

The published package manifest declares no runtime dependencies, so the npm
tarball has no runtime dependency graph. The full audit findings are still
material: CI and local Docusaurus builds consume repository-controlled and
pull-request-controlled configuration, Markdown, MDX, images, and other build
inputs. Read-only workflow permissions, bounded timeouts, review, weekly
Dependabot checks, and periodic re-audit reduce this build-time risk; they do
not eliminate it.

## Release and reassessment policy

A compatible Docusaurus or upstream fix triggers prompt reassessment, a fresh
full audit, and normal verification before acceptance. New high or critical
findings on the published surface block release. Development/build findings
remain visible and are reviewed individually; they are never masked or
described as harmless merely because the published runtime graph is clean.
